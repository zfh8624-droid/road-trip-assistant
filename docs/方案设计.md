# 行野自驾出行 · 方案设计

> 基于现有代码审计 + 用户原始意图 + 市面成熟竞品分析

---

## 一、项目定位（还原）

从 README、代码和用户原始表述综合来看，**行野**是一个：

> **面向全国自驾旅行者的路线规划工具**
> 
> - 用户输入出发地、目的地、驾驶偏好 → 自动生成多日行程
> - 每日行程包含路线、途经景点/美食、住宿安排
> - 当日目的地附近可查加油站、充电站
> - 可邀请好友同行、分享路线
> - 最终导航跳转高德地图完成驾驶

核心一句话：**帮用户做"从A到B开车玩几天"的完整攻略**，自己不做导航（调起高德），专注"规划"这一个环节。

## 二、现有代码审计

### 2.1 工程结构

```
road-trip-assistant/
├── index.html              # 单文件 Web 原型（HTML+CSS+JS，已能跑）
├── miniprogram/            # 微信小程序原生代码（功能与原型一致）
├── web/                    # Vue 3 + Vant 4 重构版（本次新做）
└── server/                 # Node.js + Fastify + Prisma + PostgreSQL 后端
```

### 2.2 现状：哪些是"写死的"

| 模块        | 现状                                                                        | 问题                                     |
| --------- | ------------------------------------------------------------------------- | -------------------------------------- |
| **路线数据**  | `stores/route.ts` 中 3 条路线（川西/滇川/甘南）硬编码，固定景点、固定 stops、固定图片                 | 用户改出发地/目的地时，实际没有真的重算路线，只是改了起止点文案       |
| **城市选择**  | 出发城市只有 7 个兜底 + jsdelivr CDN 拉取全国城市列表；目的地自由输入但不校验                          | 城市列表依赖外网 CDN，离线打不开；目的地随意输入不经过地理编码      |
| **日程生成**  | `buildSchedule()` 是纯前端按比例切 stops 数组，每个 day 固定 4 个事件模板（出发/午饭/景点/入住），时间点硬编码 | 没有真实里程/驾驶时长计算，景点与当日位置不匹配，不考虑海拔/路况/营业时间 |
| **沿途景点**  | 每条路线 4 个硬编码景点，图片来自 Unsplash，类型只有"景点/美食"                                   | 不是基于用户路线真实搜索的，景点数据无经纬度、无距离、无评分         |
| **补给查询**  | 加油站/充电站直接拼高德 URI Scheme 关键词（`uri.amap.com/search?keyword=XX加油站`）          | 不是基于当日目的地真实坐标搜最近的，没有油号/充电类型/空闲状态       |
| **城市距离**  | `distanceKm()` 用 Haversine 公式算直线距离，不是路网距离                                 | 自驾应该用驾车路线距离和时间，直线距离误差极大（山区尤甚）          |
| **好友/同行** | 本地 localStorage 存名字数组，`Invitation` 表在后端但没打通                               | 没有真实邀请链路，分享只复制文案                       |
| **收藏**    | 前端 localStorage 存景点名，后端 Favorite 表存在但没用                                   | 跨设备不同步，只支持收藏硬编码景点                      |
| **用户登录**  | 后端 `/api/auth/wechat` 写了 code2Session，前端没有微信登录流程                          | 没有 userId，所有 API 都没法真正调用               |
| **高德代理**  | 后端 `/api/amap/nearby` 写了周边搜索代理，前端没调用                                      | 高德 Key 没配，且只支持关键字周边，没有路线规划、路径距离、POI详情  |

### 2.3 现状：哪些已经有雏形（可直接用）

| 模块      | 位置                                                        | 状态                                   |
| ------- | --------------------------------------------------------- | ------------------------------------ |
| 后端框架    | Fastify + Prisma + Zod + CORS                             | ✅ 结构清晰可扩展                            |
| 数据模型    | User/Trip/TripMember/TripDay/TripStop/Favorite/Invitation | ✅ 基础表合理，少量字段需补充                      |
| 微信登录    | `/api/auth/wechat` code2Session                           | ✅ 流程正确                               |
| 行程 CRUD | POST/GET `/api/trips`                                     | ✅ 可创建含日程/途经点/成员的行程                   |
| 收藏/邀请   | `/api/favorites` `/api/invitations`                       | ✅ 接口完整                               |
| 高德代理    | `/api/amap/nearby`                                        | ⚠️ 需要扩充更多高德接口                        |
| 前端框架    | Vue 3 + Vant 4 + Pinia + Vue Router                       | ✅ 四个 Tab 页骨架已搭好，UI 风格已定调             |
| 小程序     | 原生微信小程序                                                   | ⚠️ 数据硬编码，但权限配置了 `scope.userLocation` |

### 2.4 核心问题诊断

**一句话：前端是个"看起来像真的"的高保真原型，没有真实数据、没有真实路线计算、没有接后端。**

- 所有路线/景点/日程都是写死的 mock 数据
- 改出发地/目的地只是改文案，不会真的重新规划
- 补给站搜索只是关键词跳转，不是基于位置的实时查询
- 后端虽然写了 API，但前端一次都没调用过
- 没有微信登录，用户无法和数据绑定

## 三、竞品分析摘要

调研了国内最直接的 3 款自驾类 App：

### 3.1 趣兜风（最直接对标）

- **核心**：自驾专属，不做通勤导航，专注"路线规划 + 语音导览 + 路书"
- **亮点**：
  - 全国 200+ 实测自驾线路库（川西/新疆/独库等），可一键复用
  - AI 路书生成：输入起终点+天数+偏好 → 自动排每日行程
  - 手动编辑：拖动途经点排序、增删景点/充电桩/民宿
  - GPS 触发沿途语音讲解（接近景点自动播放人文历史）
  - 沿途补给：按当前位置筛选加油站/充电桩/露营地，直接导航
  - 轨迹记录：自动记录里程/海拔/停留点，可导出分享
  - 组队出行：多人实时定位共享
  - UGC 路线：用户可发布自制路书到社区

### 3.2 窝友自驾（偏床车/房车）

- **核心**：营地数据库 + 路线规划 + 组队
- **亮点**：
  - 全国营地/驻车点数据库（水/电/卫生间标注）
  - 路线+营地一键规划，服务区加油站充电桩都在路线上标注
  - "窝窝打卡"：记录私藏景点/美食位置，形成个人地图
  - 附近窝友 + 实时组队对讲（多车出行防掉队）
  - 主题自驾活动（补贴油费拼车）

### 3.3 高德地图（基础能力供应商）

- 我们不做导航，导航全部调高德
- 高德本身有"路书"功能：收藏夹 POI 一键排序成路线
- 沿途服务一键加站（加油/充电/吃饭/厕所）
- 提供完整的 Web 服务 API（路径规划、POI搜索、地理编码、周边搜索、距离矩阵）

### 3.4 海外参考

- **Roadtrippers**：起终点输入 → 沿路线展示景点/餐厅/奇怪地标，可加入行程
- **Furkot**：根据每日驾驶时长偏好自动排多日住宿点
- **ABRP**：电动车专属，按车型/电池/天气规划充电路线
- **GasBuddy/PlugShare**：加油站比价、充电桩实时空闲+用户评价

### 3.5 竞品给我们的启发

| 能力          | 趣兜风     | 窝友自驾   | 高德  | 我们要做吗           |
| ----------- | ------- | ------ | --- | --------------- |

## 四、目标产品定义

### 4.1 一句话

**行野 = 自驾专属路书规划器**：输入起终点+天数+偏好 → 自动生成多日自驾行程（路线+景点+美食+补给） → 可调起高德分段导航 → 可邀请好友共享同一份路书。

### 4.2 不做什么（克制原则）

- ❌ 不自己做导航（全部调高德 URI / 高德导航SDK）
- ❌ 不做游记/动态/朋友圈类 UGC 社区
- ❌ 不做语音导览（内容成本太高）
- ❌ 不做车队实时位置/对讲（复杂度高，P2 再说）
- ❌ 不做酒店/门票/租车预订（重运营）
- ❌ 不做货车/皮卡/房车专属（先聚焦普通小客车，包括燃油+新能源）

### 4.3 核心用户故事

1. **小白用户**：国庆想从成都自驾去稻城，玩 7 天，不知道怎么走、每天开多久、路上有什么好玩的、在哪加油充电 → 打开行野，输入"成都→稻城，7天，轻松驾驶，自然风光+美食"，一键出完整路书，一键加入收藏，出发那天调起高德每天按日程开。

2. **情侣/朋友出行**：我和朋友两家人两辆车自驾川西 → 我规划好路线，分享链接给朋友，朋友点开能看到同一份日程，各自按自己节奏开，每天晚上汇合。

3. **有经验老司机**：我知道自己要走哪条线，想在现成路线基础上微调（某天多留半天、加一个朋友推荐的小众景点、标注自己常去的加油站）→ 选一条推荐路线，手动增删途经点，拖动排序，保存为自己的路书。

## 五、功能方案

按优先级分三个阶段落地，**P0 是 MVP 跑通真实可用**，P1 是完整可用，P2 是加分项。

### P0 · MVP（必须先做，把"写死的"变成"真的"）

#### 1. 真实路线规划（替换硬编码路线）

**现状问题**：改出发地/目的地只是改了文案，路线还是那 3 条。

**方案**：

- 接入高德 **驾车路径规划 API**（`restapi.amap.com/v3/direction/driving`），通过后端代理
- 接入高德 **距离矩阵 API**，计算每日驾驶段真实里程和时间
- 用户输入：`origin`（出发城市，经地理编码转坐标）、`destination`（目的地）、`days`（天数）、`drivePreference`（轻松/适中/高效 → 对应每日驾驶 3h/5h/7h 上限）、`preferences`（标签）
- 后端根据总里程 / 每日驾驶时长上限自动切分天数，确定每日落脚点城市
- 接入高德 **沿路线搜索 POI**（`v3/place/around?types=...` 结合路线 polyline），在每日沿途拉取景点、美食 POI
- 景点/美食按评分、距离路线偏移量、是否匹配偏好标签排序，每天选 1-2 个插入当日行程

**日程模板升级**（不再是固定 4 个事件）：

```
Day 1:
  08:30 出发 → 第一段驾驶（显示里程/预计时长）
  12:00 午餐（沿路线推荐本地高分餐厅）
  14:00 景点A（按偏好选）
  17:00 抵达落脚点城市，加油/充电提示，入住
```

#### 2. 真实城市/POI 搜索

**现状问题**：城市列表依赖外网 CDN，目的地输入不校验，景点没坐标。

**方案**：

- 后端代理高德 **关键字 POI 搜索**（`v3/place/text`）和 **输入提示**（`v3/assistant/inputtips`）
- 前端出发地/目的地改为"边输边搜"的搜索框（Vant Search + 实时调用后端 suggestions 接口）
- POI 返回经纬度、地址、评分、图片（用高德返回的 photos，无图就用占位或分类默认图）
- 热门城市列表内置兜底（30-50个自驾热门城市），无网也能选

#### 3. 真实沿途补给

**现状问题**：加油/充电只是拼关键词跳高德搜索，不是基于当日位置的真实查询。

**方案**：

- 扩充后端 `/api/amap/nearby`：
  - `keywords=加油站` + `types=011100`（加油加气站）
  - `keywords=充电站` + `types=011101`（充电桩）
  - 支持按半径、按类型（中石化/中石油/特来电/国家电网）过滤
  - 返回真实 POI 数据：名称、地址、距离、经纬度、电话
- 前端补给卡片展示附近最近的 3-5 个站，显示距离，点击调高德 `uri.amap.com/navigation` 直接导航过去
- 日程里每天的"入住"事件后自动附："建议在XX加油站加油"（根据当日落脚点位置调一次周边搜索缓存）

#### 4. 用户登录 + 数据云端存储

**现状问题**：没有 userId，API 无法调用，收藏/行程只在本地。

**方案**：

- 小程序端：`wx.login()` → 拿 code → 调 `/api/auth/wechat` → 拿 userId 存本地
- Web 端：先用"模拟登录"（本地生成随机 userId 存 localStorage），后续接微信公众号扫码/手机号登录
- 所有 POST /api/trips、/api/favorites 接口带上 userId，真正存到 PostgreSQL
- 行程可以保存为"草稿"，历史行程列表在"我的"页面可见

#### 5. 邀请好友走通真实链路

**现状问题**：邀请只复制文案，好友点了没用。

**方案**：

- 小程序：生成带 `tripId` 的小程序分享卡片（`<button open-type="share">` 已有，补充 path 带 tripId 参数）
- 好友打开分享卡片 → 进入行程详情页 → 点"加入行程" → 调 `/api/invitations` 创建 → 行程 owner 的 TripMember 里加上这个好友
- Web 端：生成分享链接（带 tripId），复制给好友，好友打开以"访客身份"查看，登录后可加入
- 同行成员可查看同一份行程（只读即可，P0 不做协作编辑）

### P1 · 完整版（P0 跑通后做）

#### 6. 路线模板库（冷启动）

- 沉淀 30-50 条经典自驾路线（川西环线、滇藏线、独库公路、青甘大环线、海南环岛、呼伦贝尔、丙察察等）
- 结构：名称、起终点、建议天数、标签、封面图、每日 stops 数组（含经纬度）、沿途精选景点/美食
- 用户可"基于模板创建我的行程"，在模板基础上改
- 模板按"出发城市就近推荐"排序（如北京用户优先推荐草原/海边路线）

#### 7. 手动编辑路线

- 日程页支持：长按拖动事件调整时间/顺序
- 景点列表支持"换一批"重新推荐（基于同样的偏好再选一批）
- 支持"添加途经点"：搜索任意 POI，手动加入某天行程
- 支持"删除/跳过"某个推荐景点
- 支持调整某一天的驾驶强度（单独一天改轻松/适中/高效，重新排当天日程）
- 编辑后实时重算总里程/总天数

#### 8. 收藏夹升级

- 收藏不只是景点，可收藏路线、收藏单个 POI
- 收藏的 POI 在规划路线时可以一键"加入我的行程"

#### 9. 行程详情页优化

- 路线地图预览（高德 JS API 画 polyline，标记每日落脚点和景点）
- 每日行程卡片：地图+事件时间线+补给信息整合
- 每个事件支持"导航到这里"按钮（调起高德导航到该 POI）

#### 10. 电动车专属（借鉴 ABRP 思路）

- 用户可选"燃油车/新能源车"，新能源车输入车型（电池容量、续航）
- 日程中自动规划充电站（按剩余续航估算什么时候需要充）
- 优先选快充、选高评分充电站

### P2 · 加分项（做了更好，不做也不影响核心）

- 历史行程归档 + 出行统计（总里程、去过城市数、驾驶天数）
- 轨迹记录（出发后开启 GPS 记录，回来生成轨迹海报可分享）
- 离线下载路线（提前缓存每日行程、景点图片、离线地图包）
- 组队模式：多人加入同行程后可看到彼此的大致位置（不做实时精准位置，隐私考虑）
- 费用 AA 记账（行程内共同花费分摊）
- 出发前 checklist（证件、装备、车况检查清单）

## 六、技术方案

### 6.1 高德 API 接入清单

后端需要代理的高德 Web 服务 API（全部通过后端走，避免 Key 暴露在前端）：

| API    | 用途                       | 端点                            |
| ------ | ------------------------ | ----------------------------- |
| 输入提示   | 出发地/目的地实时搜索补全            | `v3/assistant/inputtips`      |
| 地理编码   | 城市名/地名转经纬度               | `v3/geocode/geo`              |
| 逆地理编码  | 经纬度转地名                   | `v3/geocode/regeo`            |
| 驾车路径规划 | 起终点驾车路线、里程、时长、polyline   | `v3/direction/driving`（支持途经点） |
| 距离矩阵   | 多点间距离/时长计算（日程切分用）        | `v3/distance`                 |
| 周边搜索   | 加油站/充电站/餐厅/景点附近搜索        | `v3/place/around`             |
| 关键字搜索  | POI 详情搜索                 | `v3/place/text`               |

### 6.2 数据模型扩充（基于现有 Prisma schema）

现有 7 张表基本够用，需补充：

```prisma
// Trip 增加字段
model Trip {
  // ...原有字段
  status      String   @default("draft")  // draft | planning | ongoing | completed
  vehicleType String   @default("gas")    // gas | ev
  polyline    Json?    // 高德返回的路线 polyline 字符串
  totalDistance Int?   // 真实总里程（米）
  totalDuration Int?   // 真实总时长（秒）
  coverImage  String?
}

// TripStop 增加字段
model TripStop {
  // ...原有字段
  poiId       String?  // 高德 POI ID
  address     String?
  tel         String?
  stayMinutes Int?     // 建议停留时长
  arrivalTime String?  // 预计到达时间
  cost        Int?     // 预计花费（门票/人均）
}

// TripDay 增加字段
model TripDay {
  // ...原有字段
  startLocation String?  // 当天出发地
  distanceKm    Int?     // 当日里程
  driveMinutes  Int?     // 当日驾驶时长
  polyline      Json?    // 当日路段 polyline
}

// 新增：POI 缓存（避免重复调用高德）
model PoiCache {
  id        String   @id @default(cuid())
  poiId     String   @unique
  name      String
  location  String   // 经纬度 "lng,lat"
  address   String?
  tel       String?
  type      String   // 景点|美食|加油站|充电站|酒店
  rating    Float?
  photos    Json?
  createdAt DateTime @default(now())
}
```

## 八、关键风险与应对

| 风险              | 应对                                         |
| --------------- | ------------------------------------------ |
| 高德 API 配额/费用    | 后端代理+缓存（PoiCache 表），热门 POI 和模板路线静态化，减少实时调用 |

| 电动车规划复杂度高       | P1 先不做，P1 只做燃油车；电动车简化为"沿途搜充电站"，不做续航估算      |
| 小程序审核位置权限       | app.json 已配置 scope.userLocation，描述文字写清楚用途  |
| 多端（Web+小程序）维护成本 | 核心逻辑（日程生成、POI推荐）放后端，前端只做展示和交互，避免两端重复逻辑     |
