# 行野 · 部署指南

> 部署前请确认你已经有：
> 1. 一个可用的 PostgreSQL 数据库（本地、云端、Zeabur PostgreSQL 服务均可）
> 2. 高德开放平台创建的「Web 服务」类型 Key（前端 JS API Key 不支持服务端调用）
> 3. Zeabur 账号（推荐）或任意支持 Docker 的服务器

---

## 一、必须填写的 7 个环境变量

不管哪种部署方式，下面这些变量在服务启动入口里都会先校验，
缺关键变量会直接退出（不让服务带着坏状态起来），你照着下面清单填就行：

| 变量名 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `DATABASE_URL` | ✅ | PostgreSQL 连接串，末尾记得带 `?schema=public` | `postgresql://root:密码@43.134.10.235:32441/xingye?schema=public` |
| `TOKEN_SECRET` | ✅ | JWT 签名密钥，**至少 32 字节随机字符串**。<br>生产建议 `openssl rand -hex 32` 生成。<br>⚠️ 修改会导致所有已登录用户掉线 | `a1b2c3...（64 位 hex 随机字符串）` |
| `AMAP_KEY` | ✅ | 高德「Web 服务」类型 Key，决定地理编码/路径规划/补给能否用真实数据 | `39bee03b155bf637bed440784740d969` |
| `AMAP_SECRET` | ⚪ | 高德安全密钥（控制台启用了就填） | `b070f9fe5ba4c381257126e72dc014b6` |
| `PORT` | ⚪ | 服务监听端口，Docker 下默认 `8080`，自建可自定义 | `3000` |
| `WECHAT_APPID` | ⚪ | 微信小程序 AppID（不做小程序登录可留空） |  |
| `WECHAT_SECRET` | ⚪ | 微信小程序 Secret（不做小程序登录可留空） |  |

## 二、方式 A：Zeabur 一键部署（推荐，最省事）

> 你们之前已经有 Zeabur Docker 部署的基础链路，新 Dockerfile 直接兼容。

### 步骤 1：数据库准备（3 选 1）
- **方案 A1**：Zeabur 控制台「创建服务 → PostgreSQL」，新建服务后复制 `DATABASE_URL`
- **方案 A2**：用你现有的 PG 实例，直接新建数据库：
  ```sql
  CREATE DATABASE xingye OWNER root;
  \c xingye
  CREATE EXTENSION IF NOT EXISTS "pgcrypto";
  ```
- **方案 A3**：跑仓库里的脚本：
  ```bash
  PGHOST=43.134.10.235 PGPORT=32441 PGUSER=root \
  PGPASSWORD=你的密码 PGADMINDB=zeabur CREATEDB=xingye \
  node server/scripts/create-db.cjs
  ```

### 步骤 2：部署应用
1. Zeabur → 项目 → **「Deploy New Service」→ 选择 Git 仓库**
2. **选择分支 `develop_zfh`**（不要选 main！所有改动都在这个分支上）
3. 部署方式：Zeabur 会自动识别仓库根目录 `Dockerfile` 走 Docker 构建
4. 等构建完成（会打印日志，前端 build + 后端 build 通常 2-3 分钟）

### 步骤 3：在「Variables」面板粘贴环境变量
| Key | Value |
|---|---|
| `DATABASE_URL` | `postgresql://...?schema=public` |
| `TOKEN_SECRET` | `openssl rand -hex 32` 生成的一串随机值 |
| `AMAP_KEY` | `39bee03b155bf637bed440784740d969` |
| `AMAP_SECRET` | `b070f9fe5ba4c381257126e72dc014b6` |
| `PORT` | `8080`（留空也行，Dockerfile 默认就是 8080） |

保存后 Zeabur 会自动 Redeploy，新 Pod 启动时会自动：
```
环境变量检查 → prisma migrate deploy（建表/字段）→ 启动服务
```

### 步骤 4：验证
等 Pod 显示 Healthy → 点「Public Domain」分配的域名：
- `https://你的域名/health` → `{"ok": true}` 代表服务健康
- `https://你的域名/` → 能看到前端首页，点「生成我的行程」能真的规划出行程（真实里程/坐标）

## 三、方式 B：自建服务器 / 自家机器 Docker 部署

### 1. 构建镜像 & 启动
```bash
# 克隆/切换分支
git clone https://gitee.com/forgetting-lines/road-trip-assistant.git
cd road-trip-assistant
git checkout develop_zfh

# 构建（通常 3-5 分钟）
docker build -t xingye:latest .

# 准备环境变量文件（.env 永远不要放到 Git）
cat > /root/xingye.env <<'EOF'
DATABASE_URL="postgresql://root:你的密码@43.134.10.235:32441/xingye?schema=public"
TOKEN_SECRET="这里换成 openssl rand -hex 32 输出的随机值"
AMAP_KEY="39bee03b155bf637bed440784740d969"
AMAP_SECRET="b070f9fe5ba4c381257126e72dc014b6"
PORT=3000
EOF

# 首次启动（会自动 migrate）
docker run -d --name xingye --restart=always \
  -p 3000:3000 \
  --env-file /root/xingye.env \
  xingye:latest

# 查看启动日志，确保 migrate 没报错
docker logs -f xingye
```

### 3. （可选）Nginx 反代 + HTTPS
把 80/443 转到本机 3000，Nginx 示例：
```nginx
server {
    listen 80;
    server_name xingye.你的域名.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
然后 Certbot 一把梭：`certbot --nginx -d xingye.你的域名.com`

## 四、常见问题速查

| 问题 | 怎么排查 |
|---|---|
| **启动就退出，说缺 DATABASE_URL / TOKEN_SECRET** | 这是故意的！入口脚本在守卫变量，检查你的部署环境变量面板是否把 Key 拼对了 |
| **数据库迁移报 permission denied** | 账号没有 CREATE / ALTER TABLE 权限。给角色授权：`GRANT ALL ON SCHEMA public TO root; GRANT ALL ON ALL FUNCTIONS IN SCHEMA public TO root;` |
| **Prisma 报「Drift detected: Your database schema is not in sync with migrations」** | 手动改过表结构就会触发。干净方案：在空库上启动（会跑所有 migration）。不要在生产用 `prisma migrate dev` |
| **规划行程只有 Mock 数据（成都→都江堰这种假里程）** | 说明 AMAP_KEY 没生效：<br>1) 是否是「Web 服务」类型而不是 JS API？<br>2) 环境变量大小写是大写 `AMAP_KEY` |
| **前端页面 404，但 /health 是 OK 的** | 前端静态资源没构建成功。看 Docker 构建日志的 Stage 1 是否真的把 web/dist 打进去了 |
| **想要重新初始化数据库（⚠️ 数据清空）** | 进数据库 `DROP SCHEMA public CASCADE; CREATE SCHEMA public AUTHORIZATION root;` 然后重启 Pod，重新跑迁移 |

## 五、本地 `.env` → 线上怎么带过去？（一次性操作参考）

```bash
# 本地 cat 一下要填的值，直接复制粘贴到部署平台环境变量面板
cat > /tmp/xingye-deploy-env.txt <<'EOF'
DATABASE_URL=postgresql://root:你的密码@43.134.10.235:32441/xingye?schema=public
TOKEN_SECRET=这里换成随机值
AMAP_KEY=39bee03b155bf637bed440784740d969
AMAP_SECRET=b070f9fe5ba4c381257126e72dc014b6
EOF
```
把这 4 行粘到 Zeabur Variables，就是完整的「不会炸的部署配置」。
